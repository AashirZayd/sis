Boundary Realities

Testing shouldn't stop at the happy path.

Traditional tests validate the shapes developers expect. In production, untrusted network inputs and React Flight serialization cross boundaries with values you never thought to test.

null & undefined SIS003

Unchecked Nullish Access

Missing nested properties causing runtime crashes when destructuring unexpected network inputs. 

TypeError: Cannot read properties of undefined
NaN, Infinity & -0 SIS003

Numeric Hazards

Unchecked float singularities silently corrupting pricing, inventory, and database queries. 

RangeError: toFixed() digits argument out of range
prototype-sensitive SIS003

Prototype Pollution Traps

Adversarial inputs containing __proto__ or constructor modifying base Object behavior. 

{ __proto__: { admin: true } }
deep-nested SIS003

Deeply Nested Payloads

Multi-level object and array unpacking failing violently when encountering empty or partial trees. 

const { user: { profile: { id } } } = data;
React Flight SIS002

Serialization Violations

Non-transferable closures, class instances, or unregistered symbols crossing to Client Components. 

<ClientButton onClick={() => doServer()} />
primitive-mismatch SIS003

Primitive Type Mismatches

Stringified numbers or arrays evading loose equality checks and breaking mathematical logic. 

"42" !== 42 // triggers silent logic divergence
secret-taint SIS001

Secret Data Leaks

Private server environment variables (AUTH_SECRET, API_KEY) inadvertently leaked into client JSX sinks. 

process.env.AUTH_SECRET ──> <Profile token={...} />

Architecture Focus

Built for the boundaries where Next.js gets interesting.

Modern Next.js applications partition code across client and server environments. SIS models the exact semantic boundaries that cause production surprises.

01

Server Actions vs Server Functions

Not every server utility is an action. SIS identifies genuine client-callable entry points designated via module-level or inline "use server" directives.

02

React Server Component Boundaries

Models props passed from Server Components into Client Components against React Flight serialization protocol specifications.

03

Serializable Props Enforcement

Flags non-transferable closures, class instances, and unregistered symbols before they trigger React Flight wire serialization errors.

04

Client / Server Taint Barriers

Detects when private server credentials inadvertently leak across the network boundary into client-rendered markup.

Framework-Dependent Compatibility Gate

SIS does not attempt to emulate the entire Next.js runtime. Actions requiring live request context (e.g. cookies(), headers(), redirect(), notFound()) or external database connections are classified as static-only.

Static-only actions are safely analyzed for taint and syntax hazards without being executed in the isolate, eliminating false-positive sandbox crashes while verifying pure logic safely.

Isolate Confinement: Dynamic execution is strictly confined to zero-privilege V8 isolates with enforced CPU budgets (default: 20ms).
Developer Workflow

Zero configuration. One command.

Point SIS at your repository, directory, or individual Server Action file. 

# Audit entire repository with automatic boundary discovery
npx @aashirzayd/sis audit .

# Or using locally installed dependency:
npm install --save-dev @aashirzayd/sis
sis audit .
# Audit specific App Router directory or action file
npx @aashirzayd/sis audit ./app

# Audit a specific Server Action
npx @aashirzayd/sis audit app/actions/checkout.ts
# Output machine-readable Version 1 JSON (stdout reserved strictly for JSON)
npx @aashirzayd/sis audit . --json > sis-report.json
# Emit OASIS SARIF 2.1.0 for GitHub Security Code Scanning
npx @aashirzayd/sis audit . --sarif > sis-results.sarif
# Run reproducible speculative fuzzing with custom seed and execution budget
npx @aashirzayd/sis audit app/ --seed 42 --runs 25 --timeout 50

Frequently Asked Questions

Common questions & direct answers

Direct, definitive answers about SIS architecture, testing methodology, boundary hazards, and runtime constraints.

What is SIS?

SIS (Speculative Invariant Synthesis) is an open-source CLI runtime verification and speculative fuzzing tool for modern Next.js App Router and React Server Component boundaries. It discovers Client/Server module boundaries, traces secret data flows, models React Flight serializability contracts, synthesizes targeted adversarial payloads, and dynamically verifies invariants inside an isolated V8 execution sandbox.

What does SIS test?

SIS tests three critical boundary hazard surfaces in modern Next.js applications:

  • Server Action argument edge cases: Unexpected nullish inputs, numeric extremes, prototype pollution keys (__proto__, constructor), and deeply nested objects bypassing simple manual tests.
  • React Flight serialization boundaries: Non-transferable types (closures, class instances with private methods, unregistered Symbols) returned from Server Actions or passed across RSC boundaries (diagnostic SIS002).
  • Static secret taint leakage: Private server environment variables (*_SECRET, *_KEY, DATABASE_URL) flowing through multi-hop call graphs into Client Component JSX sinks (diagnostic SIS001).

How does SIS test Server Actions?

SIS parses source code with SWC to extract exported Server Actions (functions marked with "use server"). It infers parameter shapes from TypeScript types and destructuring patterns, synthesizes targeted adversarial payloads using fast-check, executes sandbox-compatible actions in zero-privilege isolated-vm isolates under strict CPU budgets (default: 20ms), and delta-debugs any failing inputs down to minimal reproducible examples.

Does SIS replace unit tests?

No. SIS does not replace conventional unit or integration test frameworks like Vitest, Jest, or Playwright. Conventional tests verify developer-written examples, known business logic, and happy paths. SIS complements them by exploring unanticipated boundary edge cases, fuzzing argument envelopes, and verifying unhandled runtime exceptions in an isolated sandbox.

Does SIS execute the full Next.js runtime?

No. Framework-dependent boundaries are classified as static-only when they require live Next.js request context (such as cookies(), headers(), redirect(), notFound()) or external database connections. They are analyzed statically for secret taint and return-type serializability, but safely bypassed from isolate execution to prevent artificial runtime crashes.

What is the difference between a Server Action and a Server Function?

A Server Function is any utility function executing on the server (e.g., database queries or helpers). A Server Action is an asynchronous function explicitly marked with a "use server" directive prologue, exposing a public network RPC endpoint callable from client components and browser HTTP POST requests. SIS distinguishes between the two, targeting adversarial fuzzing specifically on client-callable Server Actions.

What output formats does SIS support?

SIS supports three output formats: high-contrast human-readable terminal output, machine-readable Version 1 JSON schema via --json, and OASIS SARIF 2.1.0 via --sarif for native integration with GitHub Security Code Scanning and enterprise CI pipelines.
